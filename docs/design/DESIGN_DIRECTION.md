# 设计方向

## Design Read

像一本可操作的中文野外指南，也像一座成熟的开发者训练营；鲜明、镇定、可扫读，不仿 GitHub、不幼稚化。

设计拨盘：`DESIGN_VARIANCE 6`、`MOTION_INTENSITY 3`、`VISUAL_DENSITY 6`。落地页保留足够品牌表达；工作台提高密度并降低装饰动作。

## 视觉关键词与原则

关键词：路标、勘探图、墨色、营火橙、可信、手感、清晰。界面使用自有“村庄指南”视觉，不使用 GitHub Logo、Octocat、Primer 布局或 GitHub 像素级复制。正式课程桌面端优先，因为 Fork、Clone、终端和代码审查都发生在电脑上。

原则：每屏一个明确任务；英文永远靠近中文解释；正确与错误反馈说明原因；真实操作和模拟操作视觉上明确分层；窄屏优先保留项目介绍与回到电脑的行动指引。

## 系统

- 色彩：浅色以冷灰白和墨色为底，单一品牌强调色为营火橙；深色使用冷炭灰，不翻转成另一套品牌。
- 字体：系统中文无衬线正文，Geist 风格的拉丁界面字形与等宽命令字形。避免远程字体成为首次运行阻碍。
- 间距：4px 基线，常用 8/12/16/24/32/48/64。
- 圆角：控件 10px，内容容器 16px，状态标签使用完全圆角。三者职责固定。
- 阴影：只在悬浮导航、弹层和关键任务卡使用冷灰偏色柔影；结构主要靠留白与边框。
- 动效：只用于反馈和状态转换，150-240ms；遵守 reduced motion；不做滚动劫持与持续漂浮。
- 密度：落地页中等，工作台中高；正文宽度约 68 个汉字，命令与状态可紧凑。

## 布局依据

落地页采用非对称左文案、右侧真实游戏组件预览；工作台采用任务导航、主要模拟区、上下文词典三层结构。手机端只保证首页、第零章与演示预览可读，工作台窄屏显示“回到电脑继续”提示。响应式单栏用于防止窄窗口损坏，不代表支持在手机完成正式主线。

品牌一致性来自统一色彩、字体、路标图形语言和“证据优先”的文案语气，不靠把工作台做成营销页。

## Taste Skill 取舍

采用：Design Read、单一强调色、形状一致、非模板化 Hero、克制 Eyebrow、明确窄屏策略、完整交互状态、对比度检查、reduced motion、真实产品预览。

未采用：营销页低密度规则不覆盖工作台；不使用摄影作为教学模拟区；不使用磁吸、横向滚动劫持、玻璃拟态、GSAP 或大幅动效；工作台的章节卡与进度具有真实层级，因此允许适量容器。
