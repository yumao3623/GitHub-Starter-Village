## 第 0 章 · 村口路标｜山道连连看

**初始局面**：青砚接到四位旅人的求助：读说明、看文件、找发行附件、准备贡献副本。6×4 山道上放四块用途牌与四块入口牌，三处石障挡路；初始保证至少有一条可解路线。

**玩家目标**：为四位旅人接通正确入口，并为准备贡献的旅人规划 README → 自己的 Fork → Clone 的路线。

**可执行动作**：点选需求，再点入口；预览一条最多转弯两次且不穿石障的路径。接通后旅人走到入口，腾出一段路；可撤回尚未交付的连线。键盘方向选择、Enter 确认。

**规则与约束**：入口用途与路径可达性同时满足才成立；连线不消灭入口。读源码与取源码分别展示 Code tab 和 Code button；找桌面包须去 Releases 检查附件。连连看的转弯限制是本关规则。

**可见状态变化**：求助待接 → 路线预览 → 用途核对 → 道路开放 → 旅人抵达；右侧用途账记录已经证明的配对。

**错误与修复**：把 Fork 连到“文件已到电脑”，旅人停在账号副本门口，显示账号位置与电脑位置的差别，原路保留可改接。路径被挡只提示路线问题，不把知识判断判错。

**重玩与迁移变体**：换成“只想运行成品”的旅人，必须检查 Releases 的系统附件；另外一位直接 Clone 原仓库，证明 Clone 并非总要先 Fork。随机石障需验证可解。

**首次操作教学**：先示范接“阅读说明”到 README；下一条只突出求助牌，保留判断空间。点路牌可听青砚用完整中文解释。

**过关证据**：无提示完成新旅人的入口选择，并指出 Fork 产物在哪里、下载包从哪里找；完成旅人的实际到达，不以点过全部路牌为准。

**结算与跨章用途**：10 铜钱、入谷路引；变体首次 +5。路引在第 1 章门禁核验，领取后行囊看见签发章与用途。

**动效位置与反馈**：山道范围：接通沿路径显色 280ms，旅人行走 700ms；只在西侧现有溪流规划水面遮罩。无全屏粒子。

**正式资产**：C00-01 路牌木座；C00-02 用途布幡；C00-03 石障与桥口；C00-04 入谷旗；C00-05 路引交接托盘；C00-06 接通路段纹理。

|知识组|必须做的动作|必须看见的结果|
|---|---|---|
|`repository`、`readme`、`code-menu`、`code-tab`|辨认四类入口并把读说明｜看文件｜取源码的求助接对|相应页面用途和取用位置显现|
|`release`、`download-zip`|给运行成品与源码快照两种旅人选择交付入口|发行附件与源码 ZIP 显示不同包装与说明|
|`fork`、`clone`|对照账号副本与电脑副本并规划贡献路线|Fork 后账号站有副本；Clone 后电脑站有工作副本|

## 第 1 章 · 护身堂｜护匣守门

**初始局面**：三批各三封请求缓慢进入门庭。核验台、本人保管匣、拒绝槽各一处；第一批暂停等待操作，没有真实身份表单。

**玩家目标**：给新旧访客安排正确官方入口；把防护方法归入自己保管，把索取秘密的请求全部拦下。

**可执行动作**：展开请求看来源、需要的信息和目的；盖核验印或送拒绝槽；把防护凭据“类型牌”放到对应保管格；可暂停全部来信。

**规则与约束**：仅识别 github.com 等来源说明，不构造可输入密码的仿真登录。安全方法牌不是秘密本身；Recovery codes 不可交给 NPC。每批处置完才来下一批，速度不决定知识通关。

**可见状态变化**：请求未阅 → 检查来源与目的 → 合法入口｜本人保管｜拒绝；护匣显示身份入口、第二道防护、恢复途径三项准备状态。

**错误与修复**：把“把恢复代码交给掌柜”放进核验槽，印章不会落下，显示这类代码应由本人保管；可立即重放本封，不扣主线进度。

**重玩与迁移变体**：来信顺序和说辞改变；加入“已有账号但忘记如何设置安全”的访客以及伪装成维护者索取 Token 的请求。

**首次操作教学**：青砚演示展开来信 → 看来源 → 选择去处；第二封让玩家判断 Sign in 或 Sign up。

**过关证据**：三种危险索取全部拒绝；在变体中把身份、公开资料与安全设置分别送到正确功能处。

**结算与跨章用途**：10 铜钱、护身符；入谷路引盖核验印，后续拓印坊读取护身符作为学习条件凭证。

**动效位置与反馈**：门禁横闩 200ms 开合；拒绝时红印落在来信上 160ms；檐下已有灯笼可微摆 3deg｜6s，文字面板不跟随晃动。

**正式资产**：C01-01 护身匣；C01-02 请求笺；C01-03 核验印；C01-04 拒绝收件槽；C01-05 门禁横闩；C01-06 安全护符；C01-07 信使布包。

|知识组|必须做的动作|必须看见的结果|
|---|---|---|
|`sign-up`、`sign-in`|将新访客与旧访客请求分别送至两个官方入口说明|入口用途反馈，不发出登录网络请求|
|`username`、`profile`、`settings`|给公开名帖、资料查看和安全调整请求分流|三者影响范围分别高亮|
|`two-factor-authentication`、`passkey`、`recovery-codes`|安排防护方法和本人恢复途径，拒绝外人索取|护匣记下方法名称，永不保存凭据值|

## 第 2 章 · 拓印坊｜三台拓印机

**初始局面**：四张订单、两个工位和一个待交付格。订单分别要账号副本、本地带历史副本、源码快照、云端开发环境；交付站分为自己的账号、电脑、云端。

**玩家目标**：依据需求选择工艺和目的地，在不混淆副本关系的情况下完成全部订单。

**可执行动作**：查看订单 → 选择 Fork｜Clone｜ZIP 工艺 → 安排工位和运输 → 检查产物标签；工位冲突时调整队列。

**规则与约束**：Fork 在 GitHub 上生成归属自己的仓库；Clone 的目的地可为本地电脑；ZIP 仅交付文件快照，没有 Git 历史。工位限制是经营规则，等待可加速，不拉长学习时间。

**可见状态变化**：原项目 → 工艺选择 → 产物生成 → 归属｜位置｜历史｜关联四项检验 → 交付；错误副本不进入订单完成列。

**错误与修复**：旅人要求协作历史却拿到 ZIP：展开产物无提交册，允许免费返工换 Clone；不是用输掉一轮惩罚新手。

**重玩与迁移变体**：加入同仓库 HTTPS 与 SSH 取址订单、Codespaces 云端订单；展示 SSH 公钥与私钥的用途区别，不要求提交任何钥匙。

**首次操作教学**：先将一个原卷分配给 Fork 机，观察账号站出现副本、电脑站不变；第二单要求自主选择。

**过关证据**：交付后回答“产物在哪、谁拥有、是否有历史、是否关联原仓库”由四枚状态签自动匹配；换订单仍能独立选择。

**结算与跨章用途**：10 铜钱、拓印纸；第 3 章核验电脑工作副本和拓印纸，ZIP 也可运行但不能被描述成 Git Clone。

**动效位置与反馈**：机台压印 380ms、产物装订 350ms，运输沿工位到交付站路线 600ms；只运产物，背景不整体滑动。

**正式资产**：C02-01 Fork 拓印机；C02-02 Clone 装订机；C02-03 ZIP 包扎台；C02-04 原卷与副本册；C02-05 产物检验架；C02-06 运输马车；C02-07 工位木托。

|知识组|必须做的动作|必须看见的结果|
|---|---|---|
|`fork`、`clone`、`download-zip`|根据三种订单操作不同机器并选择交付站|产生不同归属、位置、历史和关联|
|`remote`、`https`、`ssh`|为 Clone 订单选远程地址类型并核对 remote 标签|别名指向所用来源；SSH 不等于交出私钥|
|`codespaces`、`terminal`|给云端开发订单安排 Codespaces 并打开其中的命令入口说明|云端工作环境与本地电脑分开标识|

内容配置的主来源：[官方参考](https://docs.github.com/en/get-started/using-git/getting-changes-from-a-remote-repository)。逐词来源沿用词库，进入实现时按具体 UI 核验；古风玩法并非来源建议。

## 第 3 章 · 营火工坊｜引火接管

**初始局面**：炉边有项目目录、Terminal、Node.js、依赖箱、开发服务与 localhost 展示窗。管口连通关系错放两处，日志卷显示当前失败原因。

**玩家目标**：在正确项目目录内准备运行条件，安装依赖并启动服务，访问展示窗后安全停止。

**可执行动作**：旋转｜连接管件；选择当前目录；查看日志；选择 npm install、npm run dev；停止当前进程再排错重启。

**规则与约束**：先确认项目声明的运行环境；依赖安装成功不代表服务器已启动；端口地址仅在服务运行时可访问。工具都在本地模拟，无真实 shell 执行。

**可见状态变化**：目录未就绪 → 环境符合 → 依赖已备 → 服务运行 → 浏览器访问；停止后本地窗熄灭，依赖箱仍在。

**错误与修复**：在错误目录点 npm install，日志写“此处没有项目说明的 package.json”，连接不生效；重选目录后保留已做正确步骤。

**重玩与迁移变体**：给出端口占用和依赖未准备两个不同局面，先读日志再改对应接头；不允许盲目重复所有命令算过关。

**首次操作教学**：先展示当前目录与日志的位置，用一根有效管路示范状态变化；后续接法由玩家完成。

**过关证据**：修复一个陌生日志断点并说明 localhost 为本机运行地址；停止服务后识别为何页面不可访问。

**结算与跨章用途**：10 铜钱、营火凭证；允许花 5 铜钱购买可选“提前看一个故障位置”，免费分步提示始终存在。

**动效位置与反馈**：火苗仅在炉口遮罩内随服务运行点亮；故障时火势收小、日志展开 240ms；无响应状态不能只靠颜色。

**正式资产**：C03-01 运行炉膛；C03-02 目录木匣；C03-03 依赖材料箱；C03-04 管路接头；C03-05 日志长卷；C03-06 服务观察窗；C03-07 风箱开关。

|`nodejs`、`npm`、`dependency`、`installation`、`npm-install`|根据项目说明接通运行条件并准备依赖|环境满足与依赖安装状态分别变化|

## 第 4 章 · 藏图阁｜叠卷寻证

**初始局面**：三层书架摆十二册证据，有遮挡关系；托盘四格。五条来访问题依次出现，如“能否使用”“这次发布来自何处”。

**玩家目标**：从当前仓库状态取出能回答问题的证据，组成合法证据组后归档，留够托盘空间。

**可执行动作**：取未被压住的册页；翻正查看仓库位置｜版本；配成“问题＋证据”；不需要的册页退回空位。

**规则与约束**：不是三个相同术语自动消除。证据正确且来自正确分支｜版本才归档；归档牌面不表示删除真实文件。总能免费退回，托盘满不锁死主线。

**可见状态变化**：被遮挡 → 可取 → 托盘待辨 → 证据组成立 → 问题解决；取走顶册会解开下层信息。

**错误与修复**：用 Stars 代替 License 证明使用许可，证据组退回并解释缺的是许可条件；不会奖励“猜中”而未读来源的配组。

**重玩与迁移变体**：把默认分支改名、Release 指向旧 Tag，问“当前 main 文件是否等于发行版”；玩家需查版本而非只记位置。

**首次操作教学**：演示取上层 README 露出下方 License；提示托盘只占用阅读空间，和仓库删除无关。

**过关证据**：在新的分支和版本布局中，用文件路径、提交历史和 Tag｜Release 对照完成一组证据归档。

**结算与跨章用途**：10 铜钱、藏图印；把许可证据带到第 5 章鉴宝。

**动效位置与反馈**：册页抬起 160ms、翻页 280ms、托盘落位 180ms；书架静止，无室内落叶。

**正式资产**：C04-01 多层书架；C04-02 档案册页；C04-03 四格木托盘；C04-04 版本书签；C04-05 档案问题签；C04-06 归档匣；C04-07 许可印记。

|知识组|必须做的动作|必须看见的结果|
|---|---|---|
|`files`、`folders`、`branch`、`main`|在指定分支按目录取文件证据|路径与当前分支标记同时显示|
|`commit-history`、`commits-tab`、`owner`、`contributors`|查对应历史和署名，给来源问题配证据|提交记录、仓库拥有者和贡献者不混为一谈|
|`license`、`public`、`private`|用许可和可见性册回答使用与查看问题|公开可看不等于无条件可用|
|`releases`、`release`、`tag`|将发行记录与其 Tag、附件正确配组|版本位置与发行附件并列可对照|

## 第 5 章 · 集市鉴宝｜凭据斗智

**初始局面**：三位摊主兜售三份项目卷。玩家有四个调查回合，每回合免费翻一个证据；目标明确为“允许本用途、能在给定环境运行、维护风险可接受”。

**玩家目标**：组成满足任务的证据组并选择合适项目，揭穿至少一条误导性宣传。

**可执行动作**：按 Language｜Topics 检索候选；翻 README｜Requirements｜License｜维护记录；交换一张调查牌；提出质疑；选择 0｜5｜10 铜钱的虚拟彩头后开局。

**规则与约束**：公开基础信息＋四次免费调查足以得到一个有效结论，生成局面必须满足此条件。额外线索可花 5 铜钱，但不是过关必需。对局不随机决定知识正确性。

**可见状态变化**：检索候选 → 调查证据 → 排除矛盾 → 举证质疑 → 选择交付；彩头单独显示冻结、退回或结算。

**错误与修复**：选最高 Stars 但环境不符的项目，摊主展示安装条件矛盾；允许回到证据阶段补读，不能因赢到铜钱判知识通过。

## 第 8 章 · 双城驿站｜三站运卷

**初始局面**：upstream 有 u1，origin、本地主分支与工作区均为 u0；本地还有一张未提交便条。一辆货车一次运一批已提交货件，另有远端消息册。

**玩家目标**：先获取上游情况，再整合本地并把新历史送到有权限的自己的 Fork，保持未提交便条不被误认为远端内容。

**可执行动作**：核对 origin 与 upstream 指向；派 Fetch 信使；选择本地 Pull 整合；派 Push 货车；在网页站操作 Sync fork；切换查看各站版本。

**规则与约束**：Fetch 可取回对象和远端跟踪信息，不移动本地分支或改工作区；Pull 本关采用 fetch+merge，真实项目也可配置 rebase。Push 只输送提交历史且需权限；车容量是玩法约束。

**可见状态变化**：远端实际版本、已知跟踪版本、本地分支、工作区、origin 五栏独立；每次调度高亮发生变化的栏位，未变栏保持原样。

**错误与修复**：Fetch 后点击“电脑已更新”，消息册亮 u1 而工作区仍 u0，必须继续整合；向 upstream Push 被权限挡回，不能提供 force push 绕过。

**重玩与迁移变体**：网页 Sync fork 已将 origin 更新到 u2，但电脑仍 u1；另一局本地有 c1、上游有 u2，需要先观察分叉再选整合路线。

**首次操作教学**：先对照三站版号，Fetch 第一份消息后暂停，要求玩家指出哪一栏仍未改变。

**过关证据**：给定“远端新、本地旧”陌生局面，正确使目标站收到提交，并指出未提交改动没有被 Push。

**结算与跨章用途**：10 铜钱、驿站牌；可花 5 铜钱查看可选路线预演，无钱仍有免费状态解释。

**动效位置与反馈**：Fetch 信使走轻路线 500ms，Push 货车沿桥面 750ms；桥下水域仅规划遮罩反光，不能横跨桥板；五栏状态先更新再播放。

**正式资产**：C08-01 本地站台；C08-02 origin 城门；C08-03 upstream 远站；C08-04 运卷货车；C08-05 版本货件；C08-06 远端消息册；C08-07 驿站回执。

|知识组|必须做的动作|必须看见的结果|
|---|---|---|
|`origin`、`upstream`、`local-repository`、`remote-repository`|命名三站并核对地址、归属和权限|远端别名不是权力，也不是固定的公共服务器名称|
|`fetch`、`pull`、`push`|调度消息、整合和提交货运|跟踪记录、本地分支｜工作区与远端分别变化|

## 第 9 章 · 分流竹林｜双径修路

## 第 10 章 · 合卷台｜合卷叠签

**初始局面**：8 张改动签层叠：README 南门、route.md 路线、notice.md 夜行告示为本轮三张相关签；其余为私人便条、无关配色、重复证据、未完成译文、配置误改。四个暂存操作槽，至少一条可解取签顺序。

**玩家目标**：做一次只含目标相关变更的提交，写清修改目的，再推送并核对远端回执。

**可执行动作**：取无遮挡签、查看 Diff、将所选快照放入暂存槽；退回不合适签；再次编辑工作区；封卷 Commit；交驿站 Push。

**规则与约束**：相关性决定合卷，不是三个相同牌面。四槽与遮挡是关卡规则，Git 无此限制。暂存保存操作当时的内容；再次编辑必须重新 Stage 才纳入新内容。

**可见状态变化**：工作区 W1｜暂存 S0｜本地历史 H0｜远端 R0 → Stage 后 S1 → 再编辑 W2 而 S1 不变 → 重新 Stage S2 → Commit H1 → Push R1；每栏保留可对照内容。

**错误与修复**：误收私人便条时给出具体差异，允许逐签退回；暂存后再编辑出现两版本签，必须先对照而非默默替换；槽满可以退回，不要求付钱清空。

**重玩与迁移变体**：随机遮挡与任务变更组合，相关签数量改为 2 或 4；加入暂存后修改场景，证明不存在“三张才允许提交”的 Git 规则。

**首次操作教学**：先取一张签查看 Diff，示范 Stage 后历史不变；玩家独立选择第二张，后续逐步解释封卷与交驿站。

**过关证据**：目标相关签全部且仅它们进入 Commit；说明含“修改对象＋目的”，检查新 SHA 对应的内容；远端回执与本地提交一致，操作次数不能代替知识完成。

**结算与跨章用途**：10 铜钱、合卷印；满 100 铜钱可兑换 1 张银票并记同一账，不奖励反复 Stage｜撤销。

**正式资产**：C10-01 改动签；C10-02 四槽暂存案；C10-03 Diff 对照卷；C10-04 封卷册；C10-05 合卷印章；C10-06 提交记录简；C10-07 快递封套。

## 第 11 章 · 议事堂｜合卷议事

**初始局面**：同一自己的 Fork 中 main 与 fix 分支各有改动。三位 NPC 分别关注用途、证据和维护规则；玩家手持变更说明、测试证据、修订三类行动牌，无对抗生命值。

**玩家目标**：选对 PR 方向，以有效证据回应评审，实际修订冲突内容，在模拟仓库条件满足时完成合并。

**可执行动作**：选 Base｜Head；查看 Files changed；创建 Draft、转 Ready；读 Comment/Request changes；提交修订并 Push；Resolve conversation；编辑冲突；请求复查。

**规则与约束**：意见牌效果取决于当前证据与最新提交，不按点数击败评审。Resolve 不自动 Approve；Approve 不保证允许合并。本关明确模拟规则为需批准、无冲突，自动 Checks 的完整流程在第 12 章。

**可见状态变化**：方向确认 → Draft → Ready → Request changes → 新提交回执 → 讨论已解决/重新评审 → 冲突解决 → 条件齐备 → Merge。

**错误与修复**：Base｜Head 反向时先展示将修改哪个目标；只按 Resolve 而未修订，评审仍待改；只保留冲突一侧不能通过意图核对。

**重玩与迁移变体**：评审要求从补夜行说明换成修复路线，冲突来自两种相容意图；若变更已过时必须先更新证据再求批准。

**首次操作教学**：先摆出“来源提供修改、目标接收修改”两卷，展示方向预览；第一条评论要求玩家找出缺哪份证据。

**过关证据**：新案中选对方向，真正编辑保留双方有效意图并移除冲突标记，确认最新 SHA 获得评审；不以点击所有评论为准。

**结算与跨章用途**：10 铜钱、议事令；作为第 12 章交付版本来源的凭证。

**动效位置与反馈**：意见由对应席位送来 300ms；修订展开对照页 240ms；批准印只在最新版本复查通过后落下；桌面不飘叶。

**正式资产**：C11-01 议事长桌；C11-02 来源目标卷架；C11-03 评审意见牌；C11-04 举证行动牌；C11-05 冲突合卷册；C11-06 待复查封签；C11-07 批准印。

## 第 12 章 · 百炼炉｜连炉铸卷

**初始局面**：三座工位代表检查、构建、交付；每工位有多个 Step，构建依赖检查，交付依赖构建。首次 run 绑定 c1，日志中故意缺 Changelog。

**玩家目标**：读日志修复、提交后启动读取新 SHA 的运行，完成检查并把对应产物、Tag 和发行说明装配成 Release。

**可执行动作**：搭建依赖顺序；Run workflow；展开失败 Step 日志；修改 Changelog、Commit｜Push；取消、重跑指定运行或启动新运行；核对产物与标签；发布模拟。

**规则与约束**：Cancelled 不等于 Passed；重跑旧 run 仍读取旧 SHA｜REF，不会自动获得新修复。Artifact 先于 Release 附件存在；Tag、版本号、说明、附件需一致。Pages 只是静态站点发布用途。

**可见状态变化**：待运行 → 运行中 → Failed → 修复提交 c2 → 新 run(c2) → Cancelled → 重跑 run(c2) → Passed → Artifact → Tag｜说明｜附件核对 → Release。

**错误与修复**：修复已在 c2 却重跑 c1，仍失败且突出绑定 SHA；把未通过版本产物装箱时显示内容来源不匹配，允许换回对应产物。

**重玩与迁移变体**：故障由缺变更说明换成步骤配置或任务依赖错误；插入并行可行 Job，要求观察依赖而非死记一条顺序。

**首次操作教学**：先从失败 Step 沿依赖链追到日志；示范状态火苗代表一个具体运行，不代表整个仓库永久通过。

**过关证据**：陌生故障能定位、修复、用新版本运行，再核对 Tag｜SHA｜Artifact｜Release 说明；完成后进入自己的 Fork 自查指南。

**结算与跨章用途**：10 铜钱、百炼炉印、完整游记；全通关后展示自愿答谢入口与邮箱，真实二维码未提供时赞助保持关闭。

**动效位置与反馈**：火苗在各炉口遮罩内跟随 Job 状态；失败收火 200ms、产物推出 500ms；只有实际烟口出烟。结算后保存成功再进入游记翻页。

**正式资产**：C12-01 分层百炼炉；C12-02 状态火苗层；C12-03 依赖机关带；C12-04 任务工牌；C03-05 日志长卷；C12-06 产物箱；C12-07 发行卷与标签。

|知识组|必须做的动作|必须看见的结果|
|---|---|---|
|`actions`、`workflow`、`workflow-run`、`job`、`step`、`checks`、`passed`、`failed`|安排依赖并运行，读具体失败步骤日志|每次运行、任务、步骤和检查结果分层显示|
|`changelog`、`cancelled`|修复说明并观察取消后状态|取消没有产物通过结论，新修复需新 SHA 运行|
|`artifact`、`tag`、`version`、`release`|核对来源版本并装配发行箱|构建输出和发行附件是不同阶段|
|`github-pages`|将发布后静态展示用途匹配到 Pages|显示站点与 Release 下载入口不同，不冒充已真实部署|
