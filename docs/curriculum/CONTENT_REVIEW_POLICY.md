# 内容审校政策

## 证据顺序

GitHub Docs → Git 官方文档 → GitHub Desktop 文档 → Node.js/npm 官方文档 → 当前公开界面核验 → 可靠辅助资料。

## 每次内容变更

1. 明确受影响的术语、章节、任务与界面标签。
2. 用官方页面核验定义、权限边界和当前按钮名称。
3. 更新来源、`lastVerifiedAt` 与 `uiMayChange`。
4. 检查是否把产品自己的剧情按钮误写成 GitHub 功能。
5. 检查是否暗示真实动作已被自动验证。
6. 运行三个内容命令并审阅生成报告。

## 安全与翻译

涉及密码、2FA、Passkey、恢复代码、PAT 和 SSH 时必须使用最小必要说明并链接官方文档。不得建议分享凭据。Pull Request 先解释为“合并变更提案”，再补充常见译名。一个英文词在不同位置承担不同职责时必须拆成独立条目，例如 Code 页签和 Code 菜单。

## 时效

每次发布前复核所有 `uiMayChange: true` 的 P0/P1 条目。超过 180 天未核验时，审校者应优先检查，但不能在没有证据时自动改写内容。
