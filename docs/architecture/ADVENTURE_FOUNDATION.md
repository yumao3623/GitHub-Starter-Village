# 阶段 B：可扩展历练基础

## 边界

保留阶段 A 的鉴宝规则引擎 `appraisal.ts` 和 Electron 壳。新 `adventure.ts` 在其外层管理地图、剧情、历史记录与评估。可玩课程仍只有鉴宝；飞鸽台只有剧情预告。阶段 B 不迁移旧版十四章游戏的教学完成状态。

## 数据流

```text
组件发出操作意图
  → 场景/依赖守卫
  → Zod 动作检查
  → 关卡规则引擎计算新状态
  → 纯目标谓词判断
  → 完成快照 / 地图解锁 / 宝典证据
  → v2 存档校验与本机保存
```

地图数据在 `content/world`，目标在 `content/minigames/objectives.ts`，剧情在 `content/story`，角色契约在 `content/characters/assets.ts`。`validateAdventureContent()` 纳入 `content:validate`，检查重复 ID、图环、失效先修地点、目标/术语/剧情引用和角色边界。

## 地图与剧情

- 地图坐标、道路和雾层均从地点数据生成；图与键盘地点列表使用同一 travel 动作。
- `dependsOn` 定义连接与先修路径，`requiredGoals` 定义具体操作目标。新增节点必须显式声明所需目标，不能以“前一节点能进入”代替“前一任务已完成”。
- `canEnterNode()` 未知地点与环均拒绝。直接 navigate 和 travel 均检查依赖；URL 查询参数不作为完成凭证。
- 当前完成记录从有效关内状态或完成快照推导，不存一个可任意授予的 unlocked 列表。
- 对话按 ID、所属地点、角色、台词与目标条件建模。游标、收起状态可保存；前后句有边界；跳过/重复对话不产生关卡完成记录。
- 已完成关卡复玩后，历史解锁仍保留。未交付的复玩证据不能被“开始新一轮”覆盖，返回地图也不能绕过此守卫。

## 关卡扩展契约

`MinigameAdapter<State, Intent, Rule>` 规定初态、状态转移与目标判定的职责；`evaluateGoals()` 已被鉴宝目标使用。未来每种小游戏提供自己的纯领域规则和合法动作，不把全课程变成通用选项题。

当前鉴宝动作仍为 inspect、collect、attach、verdict、deliver。动作不接受客户端 `correct` 或 `completed` 参数。五个目标检查三卷环境证据、许可证据、维护证据、有据鉴定和最终交付。

新增关卡时同时扩展内容 schema、状态/快照 schema、迁移器与解析器，编写越级、重复、重载及反例测试。**这是一套扩展基础，不是无需编写领域规则就能自动生成任意小游戏的编辑器。**

## 评估证据

查询结果分为 encountered、practiced、assessed，并标明该术语是否有当前阶段支持的目标。书签单独记录，不是成绩。

练习由具体目标满足推导。迁移评估使用与已完成练习不同的鉴宝变体；完成后保存包含完整卷宗的快照，解析时重新检查证据关系与最终结果，而不是信任一个 passed 标记。每个模式/变体最多保存一个有效收据；重复交付不重复记分。辅助评估可被后续独立评估替换，已独立通过的记录不会被较差复玩抹掉。

评估期间在任务、地图等任何视图打开宝典，都将本轮标成辅助练习。错误后允许重试；当前没有显示“首轮正确率”，也不把重试成功声称为首次答对。

仅接入 Requirements、License、Release、Archived 的有限鉴宝目标，其他词条显示“本阶段未提供评估”。没有全课程 P0 毕业、真实 GitHub 验证或防作弊服务器。用户能编辑本地文件，因此这些记录只是本地学习证据，不是防篡改证书。

## 存档迁移与恢复

| 键 | 行为 |
| --- | --- |
| `gsv:adventure:phase-a:v1` | 原始阶段 A 存档只读保留 |
| `gsv:adventure:v2` | 阶段 B 当前存档 |
| `gsv:adventure:v2:before-import[:N]` | 导入前的独立备份，不覆盖以前备份 |
| `gsv:adventure:v2:before-reset[:N]` | 重置前的独立备份，不覆盖以前备份 |

加载先读 v2；仅当该键不存在时读取阶段 A。阶段 A 校验成功后保留角色、位置、项目、资料页、收集和归档证据、错误次数、完成状态与减少动效设置；新状态写到 v2，原键不动。阶段 A 已完成记录只能成为练习快照，不能换算为独立评估。

损坏、未知版本、无效依赖、无效快照停止自动写入，不偷偷回退、重置或覆盖。备份失败时导入/重置中止。重置写入明确的新 v2 初态，避免删除 v2 后又自动加载旧 A 记录。原始记录与保留的 A 记录有独立导出入口。

浏览器同源其他窗口更新 v2 时，本窗口暂停自动保存并提示先导出再刷新；这不是联网多设备同步，也不承诺复杂并发合并。

自由探索在独立内存组件中运行，返回时原组件及其状态保留。演示也是独立内存模式。不提供这些模式的存档导入/导出入口，防止预览记录混入正式历练。

## 桌面与验证

不修改 Electron 协议、安全白名单或运行方式。桌面仍静态优先、离线读取资源，无 OAuth/API/数据库。

开发验证可用 `GSV_VERIFY_BUILD=1` 让 Next 使用 `.next-verify` 缓存，避免占用已有开发服务；Playwright 用 `GSV_TEST_URL` 指向相应本地端口。`GSV_VERIFICATION_DIR` 指定桌面验收截图/报告目录，防止覆盖阶段 A 证据。
