# 阶段 C：状态、存档和边界

在 A/B `adventure:v2` 存档上添加 `journey.simulation` 与 `journey.regions`，两者有独立版本 1。旧记录缺字段时用空状态接续；阶段 A 原键、旧课程进度与鉴宝历史不重写。

## 贡献链

`src/core/game/contribution.ts` 定义纯状态转换。组件只能发送具体意图与输入，不传 `correct: true` 或完成标志。存档保存成功操作日志和未提交表单草稿，加载时重放每个事件、校验前置条件；非法跳步日志拒绝导入，失败操作不改变模型但增加错误次数。

可观察交付物：Issue #13、三仓库版本、工作区、Diff、暂存快照、Commit 列表、已推送数量、PR、审阅、冲突结果、Workflow 状态、Release 与分支删除。重试原地继续；重复提交/推送/发布返回 info，不增加第二份交付物。

地图和场景入口都使用同一依赖判定。第 7 章先完成 A/B 鉴宝，第 8—12 章逐章依赖；藏经院依赖第 12 章。只改 URL 或点击锁定按钮不能绕过 reducer。点击已完成章节仅回看或允许符合当前模型的操作，不回滚后续事实。

重新练习贡献链需要确认，归档最近三轮有效日志，清空这一轮 C 状态；A/B 鉴宝与角色不变。旧浅层选择切片的 `journey.contribution` 字段保留但不计入新游戏完成条件，避免把旧选项成绩冒充新操作能力。

## 区域支线

`regions.ts` 分别维护物品位置、已核对域名、通知设置/投递结果与治理文书/私密渠道。恢复检查值与场景允许目标一致；重布只清空一个区域。学习动作不执行网页登录、终端、真实通知或漏洞发送。

## 真实实践

`practice-storage.ts` 使用独立 `gsv:field-practice:v1`，只保存已知步骤 ID。它是自查，不参与模拟成绩，也不声称远端验证；未知版本/损坏记录不覆盖。静态说明可以离线阅读，完成真实操作需要另行访问 GitHub。

## 演示与权限

沿用 A/B 演示隔离，不读取用户主线记录。为了不伪造后置交付物，六章贡献链在演示中也遵守依赖；当前尚未提供各章预置快跳。桌面协议、CSP、沙箱与官方外链白名单保持原有机制，无新增 IPC、数据库或网络读取账号。
