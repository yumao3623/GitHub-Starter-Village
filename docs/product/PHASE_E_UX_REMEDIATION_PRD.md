# 阶段 E：江湖闯关体验修复需求

状态：**待审核，尚未实施**  
版本：v0.1 · 2026-09-11  
前置：阶段 A—D 已在当前分支交付；本文件针对实际体验问题，不假定旧实现已经满足这些要求。

## 1. 目标与非目标

目标是让一个完全不懂 GitHub 的玩家清楚地知道“我现在在哪、要做什么、为什么这样做、完成后会去哪”，并且愿意完成下一关。

本阶段不扩展 OAuth、GitHub API、联网账号、真实 GitHub 自动验证、手机游戏或大型 3D 世界；仍然坚持真实操作必须在 GitHub 官方页面/Desktop 完成，游戏内仅记录模拟结果或玩家自述。

## 3. 章节页面隔离（E-01）

### 3.1 页面结构

进入第 7—12 章后，页面只呈现该章的：场景、NPC、任务目标、操作区、当前反馈、宝典入口、设置、退出到地图。隐藏其它章节的卡片、下拉跳关、地图节点和“下一章”直接入口。

完成页只有两个明确动作：

- `返回江湖地图`：保存本章并回地图，由地图展示解锁动画。
- `再练一次`：留在本章重新开始，不改变解锁顺序。

“武林宝典”是全局学习工具，不算章节跳转；打开后关闭仍返回同一章、同一操作步骤。设置、存档导出和安全说明同理。

### 3.2 路由与状态规则

- 章节使用稳定 URL，例如 `/adventure/lesson/7`，但服务端和客户端都调用同一个 `canEnterLesson()`；改 URL 不能越级获得主线进度。
- `/adventure` 是统一武侠壳；地图和章节是同一产品内的视图，不再链接到旧 landing/play 体验。
- 章节渲染器只接收当前 `lessonId`；不得在章节组件里渲染其它章的任务数据。
- 完成后先产生 `lesson-completed` 事件，再回地图执行“散雾—主角移动—下一节点可进入”。刷新或重复进入不得重复发奖。
- Demo 可跳关，但显示“演示模式”，不写正式存档；自由探索是只读预览，不是主线跳关。

### 3.3 验收场景

1. 在第 7 章中，页面不存在第 8—12 章按钮或章节卡片。
2. 点击浏览器后退、刷新或手动改 URL，不会把锁定章标为完成。
3. 7 章完成后回地图，只有符合顺序的 8 章变为可进入。
4. 关闭宝典再回到第 7 章，之前拖放/编辑状态仍在。
5. 用键盘可完成“退出到地图”，焦点回到对应地图节点。

## 4. 人物落地与透明素材（E-02）

### 4.1 统一渲染契约

每个角色资产必须有透明 PNG/WebP 或 SVG、原始画布尺寸、透明裁切框、脚底基线、视觉中心、默认朝向和适用动作。`CharacterArt` 不再只依赖宽高比例；场景实例必须声明 `groundY` 和 `footOffset`。

场景中角色采用：

```text
角色容器 bottom = groundY
角色脚底 anchor = 100%
投影/阴影位于 anchor 下方 2—6px
角色本体不使用灰色背景或 CSS 色块遮掩脏边
```

地图、集市、驿站、议事堂和结算页使用同一锚点函数；不能每个组件自己猜 `bottom` 或 `top`。

### 4.2 裁切和融合

- 重新导出三位主角各动作的透明版本，去除灰色/白色抠图边缘；检查 200% 和实际尺寸下的 halo。
- 对半透明发丝、猫毛、衣摆保留合理边缘，不用暴力阈值把细节削掉。
- 每个场景加入独立软阴影（椭圆或脚底墨迹），阴影颜色采自场景地面而非统一灰色。
- 角色大小按场景透视表决定，禁止通过拉伸图片弥补人物位置错误。
- 背景要预留人物安全区；不可让桌面、摊位或对话框遮住脚底。
- 使用 `object-position`、裁切框和基线数据修复构图，不用负 margin 临时推图。

### 4.3 素材验收表

每个角色 × 每个关键场景至少检查：脚底接触、阴影方向、边缘透明、尺寸比例、衣饰/花纹一致、动作姿态、深浅对比。任何一项失败都不能标记该素材“可发布”。

减少动态效果时，角色仍然落地；动画结束回调不能负责定位或通关。

## 5. 单一武侠产品壳（E-03）

左上角品牌点击应回到武侠游戏地图或角色选择，不再回到旧版营销页面。旧版页面保留的内容拆成：

- 地图内“出发说明”：下载、真实 GitHub、课程安全边界。
- 设置/关于中的“项目介绍”：开源声明、来源和非官方声明。
- README/START_HERE：源码运行和 Fork/Clone 指南。

如果旧路由仍需兼容，使用重定向到 `/adventure` 或 `/start`，不得并行保留另一套视觉导航。首页可以作为对外介绍，但从游戏工作台不应出现“跳出到另一产品”的品牌动作。

验收：从角色选择 → 地图 → 任意章节 → 完成 → 地图，全程标题、配色、图标、页脚和导航属于同一武侠产品；不出现旧版卡片、旧版主色或与游戏无关的 landing CTA。

## 6. 0—12 章完整小游戏矩阵（E-04）

每章必须提供至少 3 个有因果关系的动作，且动作改变场景状态。选择题只能作为其中一步，不得是整关。

| 章 | 场景玩法 | GitHub 能力 | 完成后的剧情交付物 |
| --- | --- | --- | --- |
| 0 村口路标 | 在仓库导览中找 README、Release、Code 与 Fork | Repository、README、Fork、Release | 获得夜行图残页 |
| 1 护身堂 | 检查官方域名、分类安全物件、拒绝索要凭据的假信使 | Sign in、2FA、Passkey、Recovery codes | 获得护身符（仅剧情道具） |
| 2 拓印坊 | 比较 Fork、Clone、ZIP 三种复制后的连线和历史 | Fork、Clone、Download ZIP、remote | 打开自己的拓印台 |
| 3 营火工坊 | 选择目录、安装依赖、启动/停止本地营火并处理缺依赖 | Node.js、npm、localhost | 点亮村口营火 |
| 4 藏图阁 | 探索文件、分支、提交历史、许可证和 Release 柜 | Files、Branch、Commit、License、Tag | 发现南北门线索 |
| 5 集市鉴宝 | 收集环境/许可证/维护线索，给候选项目贴证据签 | Search、Stars、Requirements、License、Archived | 选出可调查的工具 |
| 6 飞鸽传书 | 将收藏、通知、关注、复制任务送到不同信鸽台 | Star、Watch、Follow、Notifications、Fork | 收到维护者委托 |
| 7 悬赏亭 | 写现象/复现/期望，分类 Issue，检查重复 | Issue、Open、Label、Assignee、Milestone | 任务正式立案 |
| 8 双城驿站 | 在本地、origin、upstream 间观察和传递提交 | Fetch、Pull、Push、Sync fork、Remote | 修复分支有了来路 |
| 9 分流竹林 | 建分支、编辑、看 Diff、Stage、Commit、Push | Branch、Diff、Stage、Commit message | 修复卷宗完成 |

第 1—6 章不得用“完成贡献链前置”当作暂时缺省；它们是主线而非占位剧情。内容数据需一章一个 `lessonId`，一个可执行玩法类型和独立测试，不允许任务工厂给所有章生成同一个 options task。

## 7. 从左到右的地图解锁（E-05）

### 7.1 推荐规则

采用单条主路，从左向右推进：0 → 1 → 2 → … → 12。每完成一章只解锁下一章；为了减轻等待，可在完成一章后同时显示下一章轮廓和“宝典支线”，但支线不能替代下一主线节点。

不采用“完成任意区域即解锁另一侧区域”的网状规则。这样符合玩家理解的行进方向，也防止左边还有锁、右边已经可玩的视觉矛盾。

地图状态：

- 未开始：节点和道路被迷雾覆盖，仅显示名称与前置。
- 当前：主角站在节点左侧脚印处，目标牌和箭头只指向下一处。
- 完成：道路从当前点向右着色，印章出现。
- 可进入：下一节点亮起，其余节点仍为轮廓，不显示可点击状态。
- 已完成回看：可以复习，但不会移动主线人物或重新解锁。

地图宽屏采用可滚动卷轴；主角移动动画必须沿已完成道路向右，禁止用 `current.x/current.y` 任意跳跃。路由、按钮、地图节点和存档读取都调用同一依赖图，并用测试覆盖“不能越级、不能回退解锁、刷新可恢复”。

### 7.2 地图信息层级

地图只告诉玩家：现在位置、下一目标、完成印章、锁定原因和宝典入口。详细任务目标留在章节页，避免地图同时变成任务日志和百科全书。

## 8. 小白友好与提示教练（E-06）

### 8.1 首次进入三步教学

每个章节首次进入固定显示：

1. **看这里**：高亮唯一第一步，并用短句说明要找什么。
2. **做这一件事**：完成一步后才揭示下一步；其余可点击物件暂时降噪。
3. **为什么**：动作成功后用一句中文解释它对应的 GitHub 概念。

玩家可以关闭引导，但“重新显示本步提示”始终可用。提示关闭不改变完成条件。

### 8.2 交互护栏

- 可操作物体有明确 hover/focus 状态、动词标签和英文原词；不可操作装饰不使用按钮语义。
- 拖拽提供点击式替代；文本编辑提供可见光标、示例和撤销。
- 重要动作有确认前预览，如“将这份修改放入 Stage”；错误动作不消耗生命、不清空进度。
- 首次失败显示“你做了什么 / 目标是什么 / 下一步怎么改”，不是只显示红色“错误”。
- 可随时打开当前关卡的“任务卡”，显示 1/3、2/3 操作进度，不提前泄露答案。
- 默认中文全辅助；挑战模式仅减少提示，不减少操作说明或可访问标签。
- 键盘：Tab 顺序与视觉顺序一致，Enter 选择，Esc 返回/关闭，方向键在地图节点间移动。

### 8.3 难度阶梯

普通模式先给固定场景和少量物件；完成后再给一项变体。挑战模式更换项目资料或分支名称，不通过缩小点击目标、加快计时或隐藏必要信息制造难度。没有倒计时和体力。

验收邀请至少一名第一次接触 GitHub 的内部测试者：在没有口头解释下能找到第一步，知道如何请求提示，失败后能说出下一步。没有真实测试数据时不得在文档中声称“已验证小白友好”。

## 9. 游戏吸引力与学习效果（E-07）

### 9.1 每关的可玩闭环

```text
剧情悬念 → 明确委托 → 探索/操作 → 风险或取舍
→ 即时反馈 → 交付物进入背包/地图 → 下一关钩子
```

每关开头交代“为什么是你、为什么现在”；中段让玩家做一次有理由的取舍；结尾让 NPC 使用玩家刚交付的结果。奖励是道路、线索、印章和故事，不是虚构金币或战力。

### 9.2 不用装饰冒充学习

每个可玩动作绑定 `actionEvidence`：它改变的场景状态、对应术语、成功条件、错误原因和可迁移测试。P0 只有完成独立操作和迁移评估才算掌握；动画、剧情播放和点击“交付”不算掌握。

前六章重点建立“我做得到”的低门槛反馈，7—12 章逐步形成贡献链。每关结束显示一张“我刚学会什么”卡：英文、中文含义、刚才的动作、GitHub 真实页面中在哪里见到。

### 9.3 让人愿意继续

- 地图每次只展示下一处可达目标，同时保留右侧未知轮廓。
- 每章结尾留一个具体问题，而不是泛泛“恭喜完成”。例如鉴宝后出现维护者的新信件，说明为何需要 Issue。
- 角色在动作中有短表情反馈，但不过度跳过解释；跳过剧情不会跳过教学步骤。
- 用一次完整可完成的 5 章竖切片做留存体验评估，再扩展其余章节；不一次生成十四张空洞场景。

## 10. 武侠图标系统（E-08）

建立 `iconKey` 语义映射，禁止页面直接散落通用 Phosphor 图标：

| 语义 | 暂定图标 | 适用位置 |
| --- | --- | --- |
| 地图 | 山河卷轴 | 地图、返回地图 |
| 章节/任务 | 悬赏令 | 任务卡、节点 |
| 武林宝典 | 线装秘籍 | 词典、提示 |
| Fork | 双印拓本 | 复制到自己账号 |
| Clone | 行囊拓印 | 下载到本地 |
| Commit | 封印竹简 | 提交 |
| Branch | 分流竹枝 | 分支 |
| Pull Request | 合卷卷轴 | PR |
| Review | 朱批印 | 审阅 |
| Checks/Actions | 百炼炉/火印 | 自动检查 |
| Release/Tag | 出关令牌 | 发布/版本 |
| 安全 | 护身锁 | 账号安全 |

首选原创 SVG 线稿与 CSS 状态，不用 GitHub Logo、Octocat、商业武侠 IP、emoji 充当正式图标。图标旁始终保留中文/英文文字，不能靠图形单独传递关键含义。图标需有默认、hover、focus、disabled、success、error 状态和 16/20/24px 可读性验收。

## 11. 数据与工程拆分

建议调整而非立刻实施：

```text
src/content/world/linear-route.ts       # 0—12 单向节点与先修关系
src/content/lessons/zh-CN/chapter-*.ts  # 一章一玩法、一章一剧情交付
src/content/characters/anchors.ts       # groundY、footOffset、资产裁切
src/content/icons/wuxia-icons.ts        # 语义 iconKey 映射
src/core/game/lesson-gate.ts             # 页面/路由/地图共同调用
src/core/game/action-evidence.ts         # 每个动作的学习证据
src/components/adventure/lesson-shell.tsx # 独立章节壳，无章节导航
src/components/adventure/grounded-character.tsx # 统一落地渲染
```

保留现有 Next.js/React/TypeScript/Zod 和本机存档，不添加数据库或 GitHub API。阶段 E 可先用 CSS/SVG 和批准的样板图验证，不在没有角色资产验收前批量生成所有背景。

## 12. 阶段 E 实施顺序

1. **E0 体验基线**：录制现有 0—12 章，列出每章可见入口、人物基线和当前解锁状态；保存问题截图，不改代码。
2. **E1 章节隔离＋单向地图**：先改路由/状态机和返回地图，补越级、刷新、重复完成测试。
3. **E2 落地样板**：选第 5、7、9 章各一个背景，完成三角色透明裁切、脚底锚点、阴影和边缘验收。
4. **E3 前六章竖切片**：先做第 0—3 章低门槛玩法，再做 4—6 章探索/鉴宝/信使，验证新手能走通。
5. **E4 提示教练＋图标**：统一第一步引导、任务卡、错误反馈、键盘替代和武侠 iconKey。
6. **E5 吸引力调优**：贯通 0—12 故事交付物，加入复玩变体、章节悬念和学习证据；用固定样本走查，不虚构用户留存。
7. **E6 回归验收**：桌面目标尺寸、键盘、减少动态、控制台、存档、Demo、P0/P1 内容覆盖和构建测试。

## 13. 阶段 E 验收清单

- [ ] 从地图进入章节后，看不到其它章节入口；完成/退出才可回地图。
- [ ] 第 0—12 章均有独立可操作玩法和至少三步状态变化。
- [ ] 地图节点严格从左到右，只开放下一个主线节点；主角不跳点。
- [ ] 角色在五类场景脚底接触地面，透明边缘无灰色 halo，阴影方向正确。
- [ ] 点击品牌始终回到武侠产品壳，不出现两套导航系统。
- [ ] 新手第一次进入每章能找到唯一第一步；提示、撤销、错误解释和键盘替代可用。
